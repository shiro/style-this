`styled` creates a component with styles attached. It's available for React
(`@style-this/react`) and SolidJS (`@style-this/solid`) with the same API.

<Tabs syncKey="framework">
<TabItem label="React">
```tsx
import { styled } from "@style-this/react";

const Button = styled.button`
  border: 1px solid blue;
  border-radius: 2px;
`;

<Button onClick={save}>Save</Button>;
```
</TabItem>
<TabItem label="Solid">
```tsx
import { styled } from "@style-this/solid";

const Button = styled.button`
  border: 1px solid blue;
  border-radius: 2px;
`;

<Button onClick={save}>Save</Button>;
```
</TabItem>
</Tabs>

Like `css`, the template is compiled away: what remains is a thin component rendering the element
with a static class name. Everything from [Writing styles](/guides/css/) works inside the template,
static interpolations are [evaluated at build time](/guides/evaluation/).

The component accepts all props of the element and passes them on, including `ref`. In React the
component is wrapped in `forwardRef`, so refs work on React 18 as well.

## Dynamic styles with `styleProps`

Function interpolations are evaluated at render time. Declare their inputs as a type argument,
callers pass them through the `styleProps` prop.

```tsx
const Button = styled.button<{ size: number; color: string }>`
  padding: ${({ size }) => `${size}px`};
  background: ${({ color }) => color};
`;

<Button styleProps={{ size: 8, color: "green" }}>Save</Button>;
```

Each function compiles to a CSS custom property that's set through the element's `style`:

```css
.Button-b05mnk {
  padding: var(--var1-4lyfgx);
  background: var(--var2-4lyfgx);
}
```

`styleProps` is required whenever a type argument is given and is never forwarded to the DOM.

:::caution[Return complete values]
The function's result replaces the `var(...)`, so return the value with its unit:
`` ${({ size }) => `${size}px`} ``. Text after the interpolation (`${({ size }) => size}px`) ends up
as `var(--var1-…)px`, which CSS doesn't treat as a length.
:::

The functions are regular runtime code, they can use anything in scope at render time, e.g.
imported helpers or module-level values. In Solid they're tracked and re-run when the signals or
props they read change.

## Reading component props

The function argument also has a `props` field with the component's own props, so you can style
based on regular props without duplicating them.

```tsx
const Button = styled.button`
  background: ${({ props }) => (props.disabled ? "red" : "green")};
`;

<Button disabled={count >= 3} />;
```

## Extending components

`styled(Component)` extends another styled component, or any component accepting
`className` (React) / `class` (Solid).

```tsx
const Base = styled.button<{ a: number }>`
  background: none;
  padding: ${({ a }) => `${a}px`};
`;

const Extended = styled(Base)<{ b: number }>`
  margin: ${({ b }) => `${b}px`};
  cursor: pointer;
`;

<Extended styleProps={{ a: 8, b: 16 }} />;
```

- `styleProps` of the base and the extension are combined.
- The extension's classes are merged last, so its declarations win (see
  [Merging styles](/guides/merging-styles/)).

`styled("div")` is equivalent to `styled.div`.

## Overriding from outside

Classes and inline styles passed to a styled component are merged after its own, so they win.

<Tabs syncKey="framework">
<TabItem label="React">
```tsx
const override = css`
  background: blue;
`;

<Button className={override} style={{ opacity: 0.5 }} />;
```
</TabItem>
<TabItem label="Solid">
```tsx
const override = css`
  background: blue;
`;

// `style` may be an object or a CSS string
<Button class={override} style="opacity: 0.5" />;
```
</TabItem>
</Tabs>

Classes are merged with [`mergeStyles`](/guides/merging-styles/), which decides which class wins.
The custom properties of dynamic styles are combined with the incoming `style`, which wins on
conflicts.

## Using components in selectors

A styled component stringifies to its class name, so it can be used like a
[style reference](/guides/css/#referencing-other-styles).

```ts
const toolbar = css`
  .${Button} {
    margin: 0;
  }
`;
```

Components without `styleProps` also expose `.css`, the raw CSS body, for
[composition](/guides/css/#composing-styles).

## Extra classes

[`extraClass`](/guides/css/#extra-classes) works inside styled templates as well.

```tsx
const Button = styled.button`
  border: none;
  ${extraClass("btn")}
`;
```
